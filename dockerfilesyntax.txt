🧱 Dockerfile Build Command Order
Here’s the logical and execution order of Dockerfile instructions:

🔢 Ordered List
FROM

Sets the base image

Must be the first non-comment instruction

LABEL (optional)

Adds metadata (e.g. maintainer, version)

ENV

Sets environment variables for later use

ARG

Defines build-time variables (used before ENV if needed)

RUN

Executes shell commands to install packages, configure system

Each RUN creates a new layer

COPY / ADD

Copies files from host into image

ADD can also extract archives or fetch URLs

WORKDIR

Sets the working directory for subsequent commands

EXPOSE

Documents the port the container listens on (doesn’t publish it)

USER

Sets the user for running subsequent commands

CMD

Default command when container starts

Can be overridden by docker run

ENTRYPOINT

Defines the executable that always runs

Works with CMD to form the full command

VOLUME (optional)

Declares mount points for persistent data

HEALTHCHECK (optional)

Defines how to check if the container is healthy

ONBUILD (optional)

Triggers instructions when this image is used as a base

🧠 Execution Flow vs Declaration Order
Docker executes instructions top to bottom

Each instruction creates a layer

Layers are cached — so ordering affects rebuild speed

✅ Example: PHP App Dockerfile
Dockerfile
FROM php:8.2-apache

LABEL maintainer="Louis"

ENV APP_ENV=production

WORKDIR /var/www/html

COPY . .

RUN apt-get update && apt-get install -y libpng-dev zip unzip

EXPOSE 80

CMD ["apache2-foreground"]
🔍 Tips for Optimization
Group RUN commands with && to reduce layers

Place COPY after RUN if files change often (to leverage caching)

Use ENTRYPOINT for fixed behavior, CMD for defaults

🔍 What’s Happening:
MariaDB uses the Aria storage engine for internal tables (like mysql.plugin).

This blocks plugin loading, which cascades into a full MySQL startup failure.

🛠️ Step-by-Step Fix
✅ 1. Backup First
Before touching anything:

powershell
Copy-Item "C:\xampp\mysql\data" "C:\xampp\mysql\data_backup" -Recurse
🧹 2. Delete Aria Log Files
Navigate to:

Code
C:\xampp\mysql\data
Delete all files matching:

Code
aria_log.*
These are safe to remove—they’re recovery logs, not actual data.

🧪 3. Run aria_chk on Aria Tables
You’ll need to repair corrupted .MAI tables manually. Run this in PowerShell:

powershell
cd "C:\xampp\mysql\data\mysql"
foreach ($file in Get-ChildItem *.MAI) {
    & "C:\xampp\mysql\bin\aria_chk.exe" -r $file.Name
}
This repairs internal tables like mysql.plugin, user, etc.

🔧 4. Restart MySQL
